# 网页模板、验证与部署

## 参考与布局

用户参考：https://inquisitive-pony-108153.netlify.app/ 。2026-11-08 观察到：白色全屏、左上两行深灰标题、36px 左右的桌面标题、约 30px 外边距、居中大型包装。只复用展示方式，不复制该产品原稿或名称。

技能内 `assets/viewer/` 提供这一最小布局；模型与字体按系统和本地资源加载，无导航、营销卡片、自动转动或第三方统计。标题、镜头及曝光按实际模型调整，不能将模板的默认朝向当作所有包装都正确。

## 生成源码

使用可用 Python 3（脚本仅依赖标准库）：

```text
python SKILL_DIR/scripts/build_viewer.py --model OUTPUT/model.glb --title "品牌名称" --subtitle "产品包装方案" --out OUTPUT/网站源码
```

可追加 `--poster` 指定真实包装预览 PNG/JPEG/WebP，`--orbit "35deg 75deg 135%"` 指定已验证初始视角。标题只有一行时省略 subtitle。脚本校验 GLB 的结构与内嵌资源，复制本地渲染库并生成相邻的 ZIP；目标目录非空时拒绝覆盖，改用新版本目录。脚本不发布任何内容。

`vendor/model-viewer.min.js` 为官方 Google model-viewer 的固定版本副本；版本、npm 完整性与哈希记在库的 provenance 文件。更新依赖时从官方包仓库获取，保留许可证并重新验证。若本地库缺失，不用 CDN 偷换：恢复该依赖后再构建。

网页需 HTTP 服务，双击 file:// 可能无法加载模块和模型。代理运行环境须确认浏览器与本地服务在同一主机或使用支持的转发；不能把另一台机器的 127.0.0.1 当成用户可访问预览。

## 交互与质量检查

1. 桌面：首屏标题、主体占比和留白对齐参考；模型已加载而非只显示 poster。
2. 拖动后 camera orbit 实际改变，能看到背面、左右、顶底；滚轮可放大缩小且不穿模。Home 回到初始视角。
3. 手机 390×844 与横屏：标题可读，模型完整，无横向溢出；单指旋转、双指缩放（触摸未实测就记未实测）。
4. 所有运行资源本地相对路径；浏览器 console 无相关错误，模型纹理无 404。检查无 Draco/KTX 外部解码器请求和在线 HDRI 等隐藏依赖。
5. 实际断开外网或拦截外部请求仍能加载模型，才能称资源自包含；仅搜索 HTML 中没有 URL 不能证明运行时离线可用。
6. 加载失败有清楚提示，不能无限显示“加载中”。本地 ZIP 解包后文件齐全。

模型材质在网页和 Blender 中需分别检查；不得声称复杂 Blender 节点可无损变成网页材质。设备模拟结果与物理手机检查分开记录。

## Netlify Drop

只有当前任务要求部署或已有明确授权时执行；源码阶段不自动上传。用户指定 Drop 就使用 Drop，不因 Sites 可用而换托管。

1. 查当前 Netlify 官方说明：https://docs.netlify.com/deploy/create-deploys/#drag-and-drop 。准备完整可运行的静态网站目录，根目录有 `index.html`。
2. 排除 `.blend`、原始刀版、未使用纹理、个人路径、日志和密钥。网页用模型及其运行资源可以包含。
3. 在可用的用户浏览器中打开 https://app.netlify.com/drop ，确认账号/团队与目标项目；已有项目通过该项目的部署入口更新，不误改参考站。使用支持的文件/文件夹上传能力。若工具不能拖文件夹，先完成源码 ZIP 和检查，再说明具体障碍，不假称已上传；不擅自改用 CLI/API。
4. 遇账号登录、条款或其他必须由用户操作的界面，按工具规则处理；不要更改域名或访问权限来“试通”。
5. 等待实际发布结果，读取网站返回的真实 URL，检查页面、GLB 和本地 JS 均加载成功及无登录拦截。
6. 大陆访问必须以大陆实际网络测试为依据，记录测试条件。不能通过自己的代理出口访问就声称大陆可打开；无法测试时交付链接并注明尚未验证。

无部署时交付源码目录、ZIP 与本地验证记录；有部署时同时保留原文件和源码，不把托管地址作为唯一交付物。
