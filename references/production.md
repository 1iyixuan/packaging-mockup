# 建模、色彩与交付

## 几何与场景

- 区分用户给定实测尺寸和效果图估算，统一毫米或米并明确单位。无精确结构时只制作外观参考，不称生产刀模。
- 在新项目场景/副本中建立独立产品集合与摄影棚集合；原点采用产品底部中心或便于旋转的中心，并记录正面方向。
- 优先使用用户自己的真实网格、刀版或可修改几何。盒类体现厚度、折面及封口；软袋体现侧褶、封边、底部和克制褶皱。白模参考只指导外观，尺寸仍依资料。
- 做顶点/法线、穿插、接缝和正反面检查；有 UV 及可解释材质，不用仅对正面相机有效的平面贴片冒充完整包装。
- UV 直接对应原始图案。照片或效果图中的透视和光影须单独处理；不要将刀线、邻面残片或背景误贴进印刷面。
- 底面与缺失面不能凭空生成法规文字。缺少的外观区域用合理的非文字材料延续，并在交付记录说明。
- Blender 节点按类型找，例如 `BSDF_PRINCIPLED`；引擎、色彩枚举按当前版本查询，兼容失败不能默默换设置后声称相同。

## 正面 PNG 与颜色

- 严格正面用正交相机或确认透视无明显歪斜；包装四周留少量空间。先小样检查构图、颜色和透明度，再渲染长边至少 2400 px 的正式图。
- 输出 PNG RGBA、透明 film，不能把白底 JPG 改扩展名交付，也不要把透明棋盘烘进图里。
- 原稿通常作为 sRGB 颜色纹理；法线、粗糙度等数据纹理用 Non-Color。CMYK/PDF 先保留原文件并在色彩配置明确的情况下转换，不擅自覆盖。
- 使用中性背景照明和适度高光，保留原稿色相与饱和度。依据版本及实际对照选择 Standard 或 Khronos PBR Neutral 等；AgX 并非所有产品稿都适用，不能只凭设置名称认定色彩准确。
- 材质照明后的像素不会与平面原稿逐像素相同。将实际成图与原稿并排检查；不要全局提高饱和度来掩盖色彩管理错误。
- 网页 glTF/PBR 与 Blender 原生节点存在差别。程序纹理、复杂透明及凹凸等必要效果需烘焙成 glTF 支持的 PBR 贴图；几何不可被烘成一张照片来假装三维。

## 模型导出

先保存可编辑 `.blend` 并打包纹理，再仅导出产品集合。GLB 中不包含摄影棚、地面、相机和灯光；默认不使用需要在线解码器的 Draco/KTX 压缩，普通 GLB 便于国内网络及离线交付。

可在已有独立项目副本的后台 Blender 执行：

```text
blender --background PROJECT_COPY.blend --python SKILL_DIR/scripts/export_glb.py -- --collection PRODUCT_COLLECTION --output OUTPUT/model.glb
```

`PROJECT_COPY.blend`、集合名和输出路径必须替换为当前项目的实际值，使用参数数组或正确 shell 引号。脚本不建模、不渲染、不保存或覆盖 `.blend`，恢复选择状态；它检查所选集合并只导出产品网格和支持的父级对象。执行前确认该集合不混放地面等辅助网格。

如果直接在 live Blender 中导出，采用同样的限定集合策略，保留用户选择状态。必须重新载入导出的 GLB 或在网页中检查实际产品、贴图、尺寸、朝向和透明面，导出返回成功不是视觉验证。

## 推荐交付组织

```text
项目名称/
  白模参考.png
  正面效果图_透明.png
  包装模型.blend
  原稿与纹理/
  model.glb
  网站源码/
    index.html
    viewer.css
    viewer.js
    model.glb
    vendor/
  网站源码.zip
  交付记录.md
```

命名可按用户项目调整。记录来源、尺寸依据、版本、视角、色彩配置、已执行检查与未验证项。上图只是组织示例，不为已缺失产物生成假文件。后续只改稿或相机时复用现有项目，保留先前版本。
